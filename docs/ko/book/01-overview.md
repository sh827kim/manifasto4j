# 01. 프로젝트 의미와 핵심 가치

## 1) 이 프로젝트의 의미
`manifesto-java-core`는 TypeScript 원본(`manifasto-ts-core`)의 핵심 런타임/도구를 Java로 포팅한 프로젝트입니다.

핵심 목표는 두 가지입니다.
- **의미 동치**: TS와 같은 입력이면 Java도 같은 의미의 결과를 내야 한다.
- **Java 친화성**: JVM 서비스(서버, 배치, 엔터프라이즈 환경)에서 안정적으로 운영할 수 있어야 한다.

즉, 단순 번역이 아니라 **동일한 도메인 모델을 Java 생태계에서 운영 가능하게 만드는 것**이 목적입니다.

## 2) Manifesto가 해결하려는 문제
실무에서 LLM/자동화/복잡한 비즈니스 로직이 섞이면 다음 문제가 자주 생깁니다.
- 왜 이런 상태가 되었는지 설명이 어렵다.
- 재실행할 때 결과가 달라진다.
- 승인/거절 책임이 불분명하다.

Manifesto는 이를 아래 방식으로 해결합니다.
- **결정적 계산(Deterministic Core)**: 같은 입력이면 같은 결과
- **실행 분리(Host)**: 외부 I/O는 별도 실행기에서 처리
- **거버넌스(World)**: 승인/거절/라인리지 기록
- **추적(Trace)**: 결과의 근거를 추적 가능

## 3) 이 프로젝트의 핵심 약속
- Core는 순수 계산만 한다. (DB/API 호출 금지)
- 외부 실행은 Host가 맡는다.
- 승인 정책은 World가 맡는다.
- 상위 API(App)는 Core/Host/World를 조립해 개발자 사용성을 높인다.
- Compiler/Intent-IR/Translator/Codegen으로 “입력 텍스트 -> 실행 가능한 시스템” 파이프라인을 완성한다.

## 4) 신입 개발자 관점에서 중요한 포인트
- 이 프로젝트는 "객체 지향 비즈니스 로직"보다 "**데이터 기반 상태 전이**"에 가깝습니다.
- 메서드 내부에서 직접 상태를 변경하는 방식보다 `Patch`를 통해 상태를 갱신합니다.
- 오류도 예외만으로 처리하지 않고, 진단/결과 모델로 표현하는 경우가 많습니다.

## 5) 한 문장 요약
Manifesto Java는 **“설명 가능한 상태 전이 시스템”**을 Java에서 구현한 런타임/도구 체계입니다.
